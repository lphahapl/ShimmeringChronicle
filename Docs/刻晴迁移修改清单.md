# 刻晴迁移与代码合并修改清单

日期：2026-10-25。

## 使用方式

打开 `Assets/Scenes/SampleScene.unity`，场景中的玩家已替换为 `KeqingPlayer`。

- WASD：相机方向移动。
- Shift：闪避。
- 鼠标左键：空手攻击，支持提前输入接第二段。
- Tab：背包；V：任务面板；F：交互；对话中 Space：继续。
- 滚轮：选择快捷栏格子。
- 编辑器中 H：测试受伤；L：测试死亡。

背包第一格是“空手”，开局已经装备。它是正常的 WeaponSO / WeaponData 物品，有图标、两段伤害数据和一个不显示模型的武器判定预制体。可以通过背包格子重新选择装备，也可以沿用现有拖拽方式放到快捷栏。

当前动作包括待机、移动混合、转身、四向闪避、两段空手攻击、受击和死亡。尚未配置跳跃动作。

## 最终代码结构

本次按最终要求统一使用新状态机，去掉 `UsesKeqingStateMachine` 和旧移动、旧连招分支。没有保留新增的 `PlayerInputReader`。

| 文件 | 修改内容 |
| --- | --- |
| `Assets/Scripts/Logic/PlayerInput.cs` | 新增。读取全部键鼠输入，保存方向、按键结果和攻击/闪避缓存；提供 RecordInput 供验证和回放使用。 |
| `Assets/Scripts/Logic/PlayerController.cs` | 合入新工程的移动、转身、闪避、接招逻辑；使用 PlayerInput 的结果处理界面操作与动作请求；通过 CharacterController 应用根位移、根旋转和重力；只执行受击、死亡表现。 |
| `Assets/Scripts/Logic/PlayerObj.cs` | 统一维护死亡、对话、当前装备；处理伤害与韧性规则、卡肉请求和开局装备；发布装备变化、动作锁定和硬直通知。移除对 Controller 对话状态的反向查询。关闭背包后仍可获取选中物品。 |
| `Assets/Scripts/SO/PlayerSO.cs` | 新增 startingWeapon，表示从初始背包中装备哪件武器；不额外复制一份装备数据。 |
| `Assets/Scripts/Data/GameEvents.cs` | OnPlayerCombo 从只传段数改为同时传攻击者和段数。 |
| `Assets/Scripts/Logic/WeaponObj.cs` | 只接收所属玩家的攻击事件，沿用原有范围检测、伤害、特效、音效和卡肉。 |
| `Assets/Scripts/Logic/CameraMove.cs` | 从 PlayerObj 查询对话状态。 |
| `Assets/Prefabs/Player/Keqing/Imported/Scripts/ClearAttackOnStateEnter.cs` | 从源工程复制，查询正式 PlayerController 并清理连招。 |

新增及重写的 C# 逻辑使用普通 if/else，没有新增三元运算符。

## 动画事件和换武器约定

- `TryComsumeCombo`：保留源动画事件方法名，只检查接下一段，不扣血。
- `PublishPlayerCombo`：在命中帧提交攻击；PlayerObj 校验当前武器和玩家状态，然后通知 WeaponObj。
- 受击、死亡、对话和换武器会清理相应输入、连招和 Trigger，避免旧动作继续触发新武器。
- 后续武器的 AnimatorOverrideController 必须基于 `Keqing.controller` 创建。旧武器状态机不再切入；其他武器的专属动画需要按新状态机重新配置。
